# M3 durable maintenance implementation plan

**Goal:** Port the maintenance, search and destructive-operation contracts in the [approved migration plan](../superpowers/plans/2026-11-16-rust-backend-migration.md#m3--durable-maintenance-caches-search-and-destructive-operations).

**Architecture:** Extend the existing native Rust server. Retain the [M2 handoff](m2-report.md), fixture marker and process ownership; no Python runtime fallback. Keep the JavaScript frontend and Python reference intact. Use generated temporary fixtures for all write operations. [ADR](ADR-0001.md) and [contracts](contracts.md) govern API and persisted compatibility.

- [x] Record search before porting. Implement GET/HEAD book search, bounded durable FTS backfill/reclaim and invalidation. Compare typed status/body/security headers and SQLite state against unchanged Python. Check short queries, Unicode expansions and stale documents.
- [x] Port edit/original restore and trash/archive/restore/purge. Check transaction atomicity, cancelled downloads, original and orphan retention, and durable job state. Verify shared ownership, protection and cleanup queues before enabling unlink. Live fetch and scheduling are later milestones.
- [x] Port chapter and image limits/clear/legacy reclassification, bounded eviction and asset inventory/GC. Keep long file work outside SQLite transactions, hold active-reader/asset leases through blocking work, revalidate generation and ownership before deletion, preserve retryable Windows failures. Worker shutdown must join before checkpoint and process unlock.
- [x] Upgrade explicitly recognized synthetic legacy schemas only after process ownership and validation. Check restart/resume and backwards Python readability. Port explicit compaction with admission, confirmation, live job and reader checks. Leave unknown schemas fail-closed.
- [x] Run final independent review, native tests, differential and crash/recovery gates. Freeze code before timing. Run 100k chapter/512 body and 100k image metadata/zero-file cases plus 500-book/1m-chapter profiles with 512 and 10k cached bodies. Report startup/reads, eviction/GC, relevant write/delete cost, I/O/RSS and contention against the same Python corpus. Retain earlier regression suites.

The implementer owns Rust production code and README. The verifier owns new contract and recovery tests. The orchestrator owns the plan, Rust Anything CLI record/replay, final gates and delivery. Review follows implementation; the same agents handle fix rounds. Existing M2 implementation and verification sessions were checked for reuse, but their resumed runtime records retained GPT-6.1 Sol. The new role settings use GPT-6.2 Sol. No new architecture or parity discovery session is necessary.

Rust Anything is used for repository analysis and black-box HTTP record/replay on a disposable root; the existing fixture harness compares the committed database, filesystem and lifecycle behavior that HTTP recordings alone cannot capture. The approved ADR excludes the skill's optional mixed-backend front door, and the existing milestone plan takes precedence over the analyzer's generic port ordering. Do not widen tests or alter reference behavior to pass.

The orchestrator owns `rust/src/schema.rs`. Recognize the four exact legacy catalogs exercised by the pinned Python reference: missing trash column and shelf indexes, missing search subsystem, missing asset references and pending table, and the old inventory cursor and GC layout. Recheck the catalog under an immediate transaction, apply only fixed DDL, verify the upgraded fingerprint before commit, and let bounded workers populate new search and asset state. Reject unknown catalogs, including untested mixes of legacy layouts. The post-trash upgrade retains Python's appended column order and is recognized on restart.

The user approved brief startup visibility of trash already past its retention date. Python purges expired trash synchronously before accepting requests. Rust starts serving and removes eligible books through indexed background work. Test eventual disappearance and deletion state, preserve protections for active jobs, and keep the expired restore refusal.

Rust Anything 1.5.1 command sequence. Run `rust-anything analyze . --lang python --json` in the checkout. In a fresh OS-temporary root, create an oracle launcher that generates and closes an M2 synthetic fixture, settles FTS in bounded batches, and serves a fresh Python-owned copy on `PORT` with upstream fetches disabled. Supply explicit HTTP JSONL cases to `rust-anything app record --http --no-traps --inputs <cases> <temp-root> -- python -B -X utf8 oracle.py`. Confirm Python with `app replay <temp-root>`, then replay a copied native executable on an independent synthetic fixture using `--build "reader_local.exe --writable --fixture rust-fixture/library.sqlite3 --web-root web --port {port}"`. Use a fresh Rust fixture copy before replaying write cases. Retain outputs under the temporary root, with only aggregate results and limitations in the milestone report.
