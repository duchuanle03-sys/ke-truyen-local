## Platform compatibility decision

Windows Python 3.14 file validators use the open handle's 128-bit inode and ChangeTime, which stable Rust metadata does not expose. The orchestrator owns a narrow exception to the implementer's safe-Rust rule: `windows_metadata.rs` uses the official `windows-sys` bindings for two synchronous `GetFileInformationByHandleEx` calls against a borrowed `File`. Typed initialized buffers, matching information classes/sizes and immediate error propagation contain this boundary; no fallback timestamps, path reopen or Python runtime dependency. Independent review must explicitly inspect this module. All application callers remain safe Rust.

Missing upstream covers preserve the reference cover handler's 400 error wrapper; direct missing upstream images retain 503/network_error. Only injected transport diagnostic wording is excluded from comparison. Exact local URL validation and stored-cache behavior remain required.

Writable numeric conversion must preserve legal SQLite signed integers and reject binding overflow without a partial write. Shelf pagination retains its existing saturating clamp semantics. Preserve JSON integer tokens before conversion (the existing serde_json `arbitrary_precision` feature), so an out-of-range integer cannot round into a valid value before validation. Retain Python request-byte encoding detection and conversion/error distinctions; the independent review regressions define concrete boundaries.

## User-approved JSON depth exception

On 2026-11-17 the user explicitly selected: “Use a safe bound; accept and document this M2 compatibility exception.” Independent probes showed the reference settings endpoint accepts 983 nested arrays but, from 984 through at least 10,000 arrays, commits the value and then returns 500; subsequent settings HTTP reads also fail. Reproducing that failure state is excluded by this approval.

Rust allows at most 984 nested JSON containers, counting the root object or array. Thus a settings object containing 983 nested arrays is allowed; 984 arrays exceed the bound. An over-limit request returns 400 with `Dữ liệu JSON lồng quá sâu.` before any write. The shared stored-JSON parser uses the same bound. Existing over-limit synthetic metadata/settings fail safely when read; no migration, deletion or automatic repair occurs. A lower limit requires concrete platform-safety evidence and an updated report. Test supported depths, typed stored values, restart/Python readability, and over-limit rejection with unchanged state. This is an explicit compatibility exception, not a claim that Python has the same bound or failure phase.
